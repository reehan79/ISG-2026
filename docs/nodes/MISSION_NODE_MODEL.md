# Mission Node Model

**Status:** CANONICAL PROGRAMME MODEL  
**Updated:** 2026-09-23

## 1. Definition

A Mission Node is a persistent institutional/site participation identity in the MissionLab Network.

A node is not a simulator, not a separate engineering authority and not a Challenge team.

It projects approved mission information and capabilities to an institution while preserving the canonical MissionLab execution/evidence authorities.

## 2. Core identity

Conceptually a node should bind:

- institution / organization;
- site identity;
- node class;
- campaign enrollments;
- approved Experience/Profile;
- participant/team relationships;
- allowed subscriptions and actions;
- optional TwinLink resource references;
- node health / connectivity;
- evidence and event provenance.

## 3. Node classes

### Mission Hub
IST/SSTRL. Central programme coordination, Ground Support, experiment integration and evidence coordination.

### Operational Mission Node
A selected Pakistani university with a defined technical responsibility and named faculty owner.

### Participant Mission Node
A school/university taking part in the MissionLab journey, including early Challenge participants and distributed ISG-linked activities.

### National Technical / Strategic Node
A national organization contributing bounded technical/advisory capability without being treated as a paid participant.

### International Collaborator Node
A foreign university/organization participating in a controlled MissionLab collaboration. This does not make it part of the Pakistan national Ground Laboratory.

## 4. Node persistence

A node survives campaign changes.

The same node may join:

- ISG 2026;
- MissionLab Challenge 2026;
- remote KidSat missions;
- future MissionLab programmes.

## 5. Node permission principle

Every node receives only the mission projection necessary for its role.

During measured ISG episodes, nodes must not receive hidden truth, alter frozen message scripts, send uncontrolled crew advice or become required for experiment completion.

For unmeasured/showcase/Challenge missions, broader interaction may be enabled according to campaign policy.

## 6. Federation principle

The distributed network should exchange events, mission state, approved telemetry/evidence projections and submissions.

It should not create multiple competing engineering truths.

IST/MissionLab remains the programme integration point; canonical numerical execution remains in the accepted Digital Twin/Core/provider architecture.

## 7. Future physical-node extension

A Mission Node may later bind TwinLink/Edge/KidSat resources.

Physical attachment is an optional capability of a node, not a new node type and not a reason to fork the platform.
